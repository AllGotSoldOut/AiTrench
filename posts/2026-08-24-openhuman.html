OpenHuman: A Local-First AI Brain, Orchestrator, and Deep Researcher

August 24, 2026

OpenHuman (GitHub) is an open-source "AI harness" that bills itself as three things most assistants aren't: a brain with persistent local memory, an orchestrator that runs fleets of agents on durable graphs, and a deep researcher. Written in Rust (with a Tauri desktop shell), it hit ~37k stars within months of launching in February 2026 — including nine straight days as the #1 trending repo on GitHub. It's flagged early beta; expect rough edges.

What makes it different from another chat app wrapper is the memory design. Instead of vector-soup embeddings in a black box, the Memory Tree compresses your data into scored Markdown trees stored in SQLite on your machine, mirrored as an Obsidian vault you can open and edit yourself. Karpathy has publicly highlighted the approach.

Why you'd actually use it

  • You want memory you can inspect. Your world lives as editable Markdown in an Obsidian vault on disk. Auto-fetch pulls from your integrations every 20 minutes so context stays fresh.
  • You run long automations. Workflows are agent-proposed, canvas-reviewed, approval-gated runs on open-source tinyflows — durable and trigger-driven rather than fire-and-forget scripts.
  • You need fleets, not one chat. Checkpointed graph runs on tinyagents: stuck agents get steered, halted agents return a root cause, and every run replays with per-call cost accounting.
  • You're tired of API key sprawl. Managed web search (via Exa), scraper, browser, coder toolset, native Whisper voice, plus Seedream/SeedEdit image and Veo/Seedance video generation under one subscription — or point any workload at your own provider key or a local Ollama model.
  • Your assistant should live where you chat. 17 messaging channels including Telegram, Discord, Slack, WhatsApp, Signal, iMessage, plus native email over IMAP IDLE + SMTP.

One more thing worth knowing: TokenJuice compresses tool output before it hits the model — same information, up to 80% fewer tokens. Honestly, without something like that a brain this size would be unaffordable to run.

Getting started

  1. Grab the installer for your platform from tinyhumans.ai/openhuman or the GitHub Releases page. The README emphasizes UI-first setup — install to working agent in a few clicks, no config files, no terminal.
  2. Prefer your package manager? On macOS: 
    brew install --cask openhuman
  3. On Debian/Ubuntu, download `OpenHuman_<version>_amd64.deb` (or arm64) from releases, then: 
    sudo apt-get install -y --no-install-recommends ./OpenHuman_*_amd64.deb

    This lets apt resolve runtime dependencies — the docs specifically recommend it over the AppImage.

  4. On Windows, run the signed `.msi` from the latest release page.
  5. Arch users can use the in-repo AUR recipe once published: 
    yay -S openhuman-bin
  6. A script install exists but is explicitly unverified (no signature shipped): 
    curl -fsSL https://raw.githubusercontent.com/tinyhumansai/openhuman/main/scripts/install.sh | bash

    The project itself recommends the native packages instead (per official docs).

  7. Launch the app, connect integrations (Gmail, Notion, GitHub, Slack…) via OAuth, and set goals/todos from the shared kanban board.

Code & config samples

Building from source needs Git, Node.js 24+, pnpm 10.10.0, Rust 1.93.0 (rustfmt + clippy), CMake, Ninja, ripgrep, and platform desktop build prerequisites:

git clone https://github.com/tinyhumansai/openhuman.git
cd openhuman
git submodule update --init --recursive   # vendored Tauri/CEF sources
pnpm install

Dev loops:

# web-only UI work
pnpm dev

# full desktop shell
pnpm --filter openhuman-app dev:app

# pre-PR checks
pnpm typecheck
pnpm format:check
cargo check -p openhuman --lib

Troubleshooting

  1. AppImage crashes on launch under Wayland. Known issue (#2463) — can also miss `libgbm.so.1` or fail on Arch with `sharun: Interpreter not found!`. Use the `.deb` package on Debian/Ubuntu instead; env-var workarounds are documented in the issue.
  2. Script install can't be trusted / fails integrity checks. There are no `.asc` signatures for install.sh/install.ps1 yet (#2620). Prefer Homebrew, MSI, or apt installs.
  3. `git submodule update` skipped → pnpm install explodes. Vendored Tauri/CEF sources are submodules. Always run `git submodule update --init --recursive` before `pnpm install`.
  4. Summarizer failures were invisible. Older builds swallowed them silently; fixed on main (#5722). Update, then watch the run journal — every run replays with real per-call costs.
  5. Socket emits lost after a reconnect. Orphaned-emit bug patched via #5734; if workflows drop events after network blips, update first.
