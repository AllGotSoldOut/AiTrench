One CLAUDE.md File, 200k Stars: Karpathy's Coding Pitfalls as Agent Rules

August 24, 2026

andrej-karpathy-skills from Multica AI is about the simplest repo concept possible: one CLAUDE.md file that improves Claude Code's behavior. It has over 200,000 GitHub stars anyway — which tells you how badly developers wanted this.

The content comes straight from Andrej Karpathy's observations on LLM coding pitfalls: models make wrong assumptions and run with them without checking; they overcomplicate code ("a bloated construction over 1000 lines when 100 would do"); they change or remove comments and code they don't understand, even when it's orthogonal to the task. The repo turns those complaints into four enforceable principles your agent reads before every session.

Why you'd actually use it

  1. Your agent guesses instead of asking. The "Think Before Coding" principle forces explicit assumptions: state them, ask rather than guess when uncertain, present multiple interpretations of an ambiguous request instead of silently picking one. If you've ever reviewed a PR and thought "why did it assume that?", this is the fix.
  2. Small features come back as frameworks. "Simplicity First" directly targets abstraction bloat and dead code — the agent is instructed to prefer the 100-line solution over the 1000-line construction.
  3. Unrelated code keeps changing in your diffs. "Surgical Changes" forbids touching comments and code the task doesn't require. Your diffs get reviewable again.
  4. You want verifiable done-ness, not vibes. "Goal-Driven Execution" pushes tests-first and concrete success criteria, so "it works" means something checkable.
  5. You use Cursor too. The repo added Cursor support (PR #92), so the same rules work beyond Claude Code.

Getting started

  1. Grab the file into your project root: 
    curl -L -o CLAUDE.md https://raw.githubusercontent.com/multica-ai/andrej-karpathy-skills/main/CLAUDE.md
  2. Or just copy its contents into your existing CLAUDE.md. Claude Code picks up project-root instructions automatically at session start — no plugin step needed.
  3. If you'd rather install it as a skill/plugin so it applies across projects, clone the repo and follow its installation section (per official docs): 
    git clone https://github.com/multica-ai/andrej-karpathy-skills.git
cd andrej-karpathy-skills
cat README.md   # follow the plugin/skill install path for your setup
  4. For Cursor users, the README documents the equivalent placement (added April 18) — drop the same rules where Cursor reads project instructions. 
    # see the Cursor section in README.md / README.zh.md
  5. Verify it's active: start a new Claude Code session on a small ambiguous task and watch whether it states assumptions before coding. If it still charges ahead silently, the file isn't being read — check placement and path.

Code & config samples

The heart of the file is the four-principle mapping, which you can adapt to any instruction format:

| Principle              | Addresses                                    |
|------------------------|----------------------------------------------|
| Think Before Coding    | Wrong assumptions, hidden confusion          |
| Simplicity First       | Overcomplication, bloated abstractions       |
| Surgical Changes       | Orthogonal edits, touching unrelated code    |
| Goal-Driven Execution  | Tests-first, verifiable success criteria     |

Because it's plain markdown instructions, nothing stops you from trimming it to the two principles your team struggles with most, or translating the wording into your own house rules. That's arguably the best way to use it — treat the repo as a starting point, not scripture.

Troubleshooting

  1. The rules seem to be ignored. Most common cause: the file isn't in the working directory where the session starts, or you already have a large CLAUDE.md burying it. Fix: put the principles near the top of your existing CLAUDE.md and restart the session.
  2. Behavior improves for a few turns, then regresses. Long conversations dilute system-prompt-like instructions. Fix: re-anchor mid-session ("remember the surgical changes rule") or keep tasks small enough that context stays fresh.
  3. Conflicts with other instruction files. If you run multiple skill packs or a strict linter config, contradictory rules produce inconsistent behavior. Fix: deduplicate overlapping guidance and keep one source of truth per concern.
  4. The model follows the letter but not the spirit — e.g., asks about everything now. Over-eager clarification loops happen when "ask rather than guess" is applied to trivia. Fix: add a line scoping it: ask only when the answer changes architecture or data contracts.
  5. Plugin/skill install puts the file somewhere Claude never reads. This was real enough that PR #18 fixed the plugin skill path. Fix: if installing as a plugin rather than project CLAUDE.md, pull latest main and verify the installed path matches what your client loads.
