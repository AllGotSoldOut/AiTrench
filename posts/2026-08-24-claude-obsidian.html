claude-obsidian: A Self-Organizing AI Second Brain for Obsidian

August 24, 2026

AgriciDaniel/claude-obsidian is a local-first knowledge system that turns Obsidian plus Claude Code into what the README calls an "AI second brain." Drop any source — a PDF, a video transcript, a URL, meeting notes — into your vault folder, and Claude Code reads it, writes linked source-cited notes, files them into your existing graph, and answers questions grounded in what's already there. It's based on Karpathy's LLM Wiki pattern, sits at about 12,000 stars, and just shipped v2.1.0 with native Windows support.

The part I care about: your vault stays plain Markdown, JSON, and source files. No plugin cache, no cloud database, nothing silently uploaded to a model. If you bail on the tool tomorrow, you keep everything.

Why you'd actually use it

  • Research capture that actually gets filed. You've got 40 open browser tabs and a Downloads folder full of papers. Dump them in an inbox folder; Claude extracts, summarizes with citations back to sources, and links each note to related pages you already have.
  • A Notion replacement that's just files. If you want AI-assisted PKM without locking your notes in someone's cloud database, this is that — an open-source alternative where grep still works.
  • Grounded Q&A over your own reading. Ask "what did I learn about X last month?" and get answers retrieved from the vault with citations to the source notes, instead of the model guessing from training data.
  • Vault maintenance you never do manually. Explicit workflows for deduplication, orphan-note cleanup, link repair, and health checks — the chores that kill most Obsidian vaults after six months.
  • Claude Code users who want persistent memory. Skills are standard Agent Skills format (agentskills.io compatible), so the system also works with other skill-capable hosts.

Getting started

  1. Prereqs: Obsidian, Claude Code, and Python installed. On Windows, note the v2.1.0 caveat below (WSL needed for write operations).
  2. Clone the repo: 
    git clone https://github.com/AgriciDaniel/claude-obsidian.git
cd claude-obsidian
  3. Run the vault setup script to initialize a new vault or wire up an existing one: 
    ./setup-vault.sh /path/to/your/vault
  4. Open Claude Code inside the vault directory so it discovers the plugin's commands and skills: 
    cd /path/to/your/vault
claude
  5. Capture your first source — save a file into the inbox and ask Claude to process it, then retrieve with grounded answers via the wiki commands (/wiki, /save).

The repo's docs cover edge cases well: there's a dedicated installation guide at docs/install-guide.md and a Windows & WSL guide at docs/windows-wsl.md.

The vault layout stays boring on purpose:

my-vault/
├── inbox/            # drop raw sources here
├── notes/            # Claude-written, source-cited pages
├── .raw/             # original downloaded sources
└── .claude/          # skills, commands, hooks

What's new

v2.1.0 (July 31, 2026) is all about Windows. Previously native Windows crashed on every vault command with AttributeError: os has no attribute 'O_DIRECTORY' (#147). Now read-only operations — inspection, dry-runs, retrieval — work natively with equivalent safety checks (path-based alias auditing, lstat identity, symlink and junction rejection). Write operations deliberately fail closed with ERR UNSUPPORTED_PLATFORM (exit 2) before touching anything; mutations need WSL. The release also fixed CRLF handling everywhere: binary-mode reads ended false hash mismatches, and retrieval no longer returns zero results on CRLF vaults. A new windows-smoke CI job plus a 16-test compatibility suite guards against regressions. Follow-up commits on August 1 added a WSL troubleshooting guide and pointed the UNSUPPORTED_PLATFORM error at it (#152).

Troubleshooting

  • "ToolUseContext is required for prompt hooks" on session start. Cause: the SessionStart hook is configured as a prompt-type hook, which some Claude Code versions reject (issues #29 and #40 — the most-active bug reports). Fix: remove or convert the SessionStart prompt hook in .claude/settings.json, or update to the latest release.
  • /wiki and /save commands not found after git clone install. Cause: cloning the repo doesn't place commands/skills/hooks into your vault's .claude/ directory (#2), and older versions of setup-vault.sh skipped that copy step (#11). Fix: run the current setup script against your vault, or manually copy commands/, skills/, and hooks/ into .claude/, then restart Claude Code.
  • .raw folder invisible in Obsidian, breaking Web Clipper flows. Cause: Obsidian hides dot-prefixed folders by default (#5). Fix: reveal hidden files in Obsidian's settings, or configure the clipper to write to a non-dot folder.
  • ERR UNSUPPORTED_PLATFORM on native Windows. Not a bug — v2.1.0 intentionally fails closed before any write side effect; only reads work natively. Fix: perform mutations from WSL per docs/windows-wsl.md.
  • Retrieval returns zero results / false hash mismatches. Cause on pre-2.1 installs: CRLF line endings confusing text handling. Fix: upgrade to v2.1.0, which reads in binary mode and handles CRLF vaults correctly.

If you live in Obsidian and use Claude Code, this is the most complete implementation of Karpathy's LLM Wiki idea I've seen packaged for real use — and v2.1.0 finally made it usable outside Unix-land.
