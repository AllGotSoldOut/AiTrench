How to Self-Host Dify with Docker Compose

August 19, 2026 · Install · Docker · Linux / macOS / Windows WSL2

Trending: langgenius/dify — open-source platform for agentic workflows and RAG. 153k+ GitHub stars.

This is the official Docker Compose path: clone the latest release, copy .env, start the stack, then create an admin account at /install.

What you need

  • CPU ≥ 2 cores, RAM ≥ 4 GiB (Docker Desktop on Mac: give the VM ≥ 2 vCPU and 8 GiB).
  • Docker Engine 19.03+ and Docker Compose 2.24.0+ (plugin form: docker compose, not docker-compose).
  • git, curl, and jq (the clone command uses them).
  • Windows: WSL2 + Docker Desktop. Keep the repo on the Linux filesystem, not C:\.

Step-by-step

  1. Check Docker Compose

    docker --version
docker compose version

    You need Compose 2.24.0 or later. If docker compose is missing, install the Compose v2 plugin — do not use the old hyphenated docker-compose.

  2. Clone the latest release

    git clone --branch "$(curl -s https://api.github.com/repos/langgenius/dify/releases/latest | jq -r .tag_name)" https://github.com/langgenius/dify.git

    If jq is missing: sudo apt install jq (Debian/Ubuntu) or brew install jq (macOS), then rerun. To pin a tag instead:

    git clone --branch 1.x.x https://github.com/langgenius/dify.git

  3. Create the env file

    cd dify/docker
cp .env.example .env

    Edit .env only if you need custom ports, secrets, or a different vector store. Values in docker/.env override files under docker/envs/.

  4. Start the stack

    docker compose up -d

    This starts 7 core services (api, api_websocket, worker, worker_beat, web, plugin_daemon, agent_backend), 8 dependencies (Weaviate, Postgres, Redis, Nginx, SSRF proxies, sandboxes), and a one-shot init_permissions job.

  5. Verify containers

    docker compose ps

    Every service should be Up or healthy. init_permissions exiting is expected. If a service is restarting:

    docker compose logs -f api
docker compose logs -f nginx

  6. Create the admin account

    Open the installer, then the app:

    # first-run admin setup
http://localhost/install

# after that, daily login
http://localhost

    On a remote host, replace localhost with the server IP. Complete the wizard (email + password) before using Studio.

  7. Add a model (required before any workflow)

    In the UI: Settings → Model providers. Add an API key (OpenAI, Anthropic, etc.) or point Dify at a local Ollama instance. Until a default model is set, LLM blocks will fail.

Customize and restart

Change secrets or ports in dify/docker/.env, then:

cd dify/docker
docker compose down
docker compose up -d

Optional provider templates live under docker/envs/. Example — Milvus instead of Weaviate:

cp envs/vectorstores/milvus.env.example envs/vectorstores/milvus.env

Upgrade: follow the notes on the GitHub Releases page, then diff each .env.example against your .env for new variables. Pull and recreate:

git pull
docker compose pull
docker compose up -d
