Onedump: One YAML File, One Command, Every Database Backup

August 24, 2026

Onedump does one thing well: it takes database backups from MySQL or PostgreSQL and drops them wherever you actually keep backups — local disk, S3, Google Drive, Dropbox, SFTP — driven by a single YAML file. It's a Go binary with no runtime dependencies for basic MySQL dumps (it ships its own native dumper), it's in Awesome Go, and it just crossed ~990 stars after trending recently.

If your current backup story is "a cron job running mysqldump piped through gzip to a directory nobody checks," onedump is the upgrade path.

Why you'd actually use it

  • Small servers without mysqldump installed. The built-in native MySQL dumper means the single onedump binary can dump MySQL with zero external dependencies — great for containers and minimal VPS images.
  • Backing up databases behind SSH only. If your production DB isn't reachable except via a bastion, onedump tunnels the dump over SSH (sshhost, sshuser, sshkey) without you writing any tunnel plumbing.
  • Point-in-time recovery setups. binlog sync-s3 streams MySQL binlogs to S3 continuously, and binlog restore replays them to a target timestamp — the two halves of PITR without hand-rolled scripts.
  • Chasing slow queries. The built-in slow log parser turns MySQL slow logs into structured JSON, so you can pipe them into anything instead of eyeballing raw log text.
  • Cron-friendly scheduled dumps. Pass a cron expression and onedump handles scheduling itself: onedump -f config.yaml -c 21h.

Getting started

  1. Install the binary. Grab the latest release for your OS from the releases page, move it into your PATH, and make it executable: 
    sudo mv onedump /usr/local/bin/onedump
sudo chmod +x /usr/local/bin/onedump
onedump
  2. Or use Docker (recommended if you need PostgreSQL support): 
    docker run julianli/onedump:v1.5.0-amd64 -f config.yaml
    The image includes mysql client, pg_dump (both postgresql-client 15 and 16), so nothing else to install. Switch client versions with -e PG_VERSION=15. Use the amd64 tag on typical production Linux boxes.
  3. If not using Docker, install clients for the dependency-based dumpers: 
    # MySQL advanced features
apt install mysql-client
# PostgreSQL
apt install postgresql-client
  4. Write a config file with at least one backup job (see below).
  5. Run it: 
    onedump -f /path/to/config.yaml
  6. Optional: load config from S3 instead of local disk — useful for ephemeral containers: 
    onedump -f backup-config/config.yaml --s3-bucket mybucket
    It reads AWS env vars first, then the default profile in ~/.aws/credentials; override with --aws-key, --aws-region, --aws-secret.

Code & config samples

A minimal job dumping a local MySQL database, gzipped, to two destinations:

jobs:
- name: local-dump
  dbdriver: mysql
  dbdsn: root@tcp(127.0.0.1)/test_local
  gzip: true
  storage:
    local:
      - path: /backups/mydb.sql
      - path: /mnt/nas/mydb.sql

A remote database reached via SSH, saved locally and to S3:

jobs:
- name: ssh-dump
  dbdriver: mysql
  dbdsn: user:password@tcp(127.0.0.1:3306)/mydb
  sshhost: mywebsite.com
  sshuser: root
  sshkey: |-
    -----BEGIN OPENSSH PRIVATE KEY-----
    ...
    -----END OPENSSH PRIVATE KEY-----
  storage:
    s3:
      - bucket: mybackupbucket
        key: backup/mydb.sql
        region: ap-southeast-2
        access-key-id: YOURKEY
        secret-access-key: YOURSECRET

Tune concurrency and add Slack notifications:

maxjobs: 20

notifier:
  slack:
    - incomingwebhook: https://hooks.slack.com/services/XXX/YYY/ZZZ

jobs:
- name: local-dump
  dbdriver: mysql
  dbdsn: root@tcp(127.0.0.1)/app
  storage:
    local:
      - path: /backups/app.sql

The slow log parser outputs JSON you can feed straight into jq:

onedump slow -f /var/log/mysql/slow.log | jq '.results[].query_time'

Troubleshooting

  • Dump fails with spatial columns. The native MySQL dumper doesn't support spatial data types like GEOMETRY, POINT, or POLYGON. Switch that job to dbdriver: mysqldump (requires mysql-client installed).
  • PostgreSQL jobs fail on a bare binary install. Onedump has no native Postgres dumper — it shells out to pg_dump. Either install postgresql-client locally or run the maintained Docker image which bundles pg_dump 15 and 16.
  • Server rejects the connection. DSN format matters: Go-style user:password@tcp(host:3306)/dbname. A missing port defaults differently than you might expect — be explicit with :3306 for remote hosts.
  • S3 upload fails with auth errors. When credentials aren't passed inline, onedump falls back to AWS env vars then ~/.aws/credentials' default profile. In containers there is usually neither — pass access-key-id/secret-access-key in the storage block or mount valid env vars.
  • Config with secrets sitting in plaintext. Local config files contain DB passwords and SSH keys in cleartext. For anything sensitive, prefer loading the config from an S3 bucket with encryption, versioning, and IAM policies — onedump reads it straight into memory.

Onedump won't replace enterprise backup platforms, but for a solo dev or small team it covers the whole loop — dump, ship, notify, restore — with one binary and one YAML file. That's most of what people actually need.
