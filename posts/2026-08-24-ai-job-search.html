AI Job Search: Run Your Entire Job Hunt Locally with Claude Code

August 24, 2026

ai-job-search by Mads Lorentzen is an AI-powered job application framework built on Claude Code — and it's sitting at ~34,000 GitHub stars. You fork it, fill in your profile, and let Claude evaluate job postings, tailor your CV, write cover letters, and run interview prep. Everything runs on your machine; the repo's whole thesis is "the job search that runs on your machine. Fork it and own it."

The credibility part is what makes this trend: the author is a geophysicist whose position was cut in late 2025. He built this framework to run his own search — 69 tailored applications, twenty first interviews, one signed contract later he started as an AI engineer. He was upfront with every employer about using it, and it usually sparked a genuine technical conversation instead of counting against him.

One important note from the README itself: this is an independent project, not affiliated with Anthropic, and it has no cryptocurrency, token, or paid sponsorship program — anything claiming otherwise is a scam.

Why you'd actually use it

  1. You're sending out dozens of applications and every CV is generic. The framework's core loop evaluates each posting against your profile, then produces a tailored CV per role instead of one resume sprayed everywhere.
  2. Cover letters are your least favorite writing task. The same pipeline drafts them from the posting plus your actual experience, so they reference real requirements rather than boilerplate praise.
  3. You got the interview and now you're panicking. The /interview workflow preps you on the specific company and role — it researches the employer and drills likely questions.
  4. You don't want your career data in yet another SaaS. Everything is local files in your fork. Your profile, your documents, your machine. That also means full control over LaTeX output if you care about typography.
  5. You want to customize how applications work. Because it's a fork-and-own repo, you can change the evaluation prompts, add portals, or enforce your own formatting rules without waiting for a vendor.

Getting started

  1. Fork and clone the repo (forking matters here — you'll be committing your personal profile): 
    git clone https://github.com/<you>/ai-job-search.git
cd ai-job-search
  2. You need Python and a Claude Code subscription/API access. Install dependencies: 
    pip install -r requirements.txt
  3. Fill in your profile — your background, skills, and base CV live as editable files in the repo (per official docs). This is the input everything else tailors from. 
    $EDITOR profile/
  4. Evaluate a posting before you waste time applying: 
    /scrape <job-posting-url>
  5. Generate tailored documents for a posting you like: 
    /apply <job-id>
  6. When the callback comes, prep: 
    /interview <company>

Code & config samples

Output documents compile through LaTeX, which is why the CI includes a LaTeX smoke test. If you want Debian-packaged TeX Live locally (the exact combo their new CI leg tests), that's:

sudo apt install texlive texlive-latex-extra
latexmk -pdf output/cv.tex

Portal integrations ship as small CLIs with strict contracts — since v1.6.0 every portal CLI rejects unknown flags outright, exiting 1 with a structured error instead of silently returning junk. If you script around them, check the exit code, not just stdout:

portal-cli search --query "ml engineer" || echo "bad flags or failed scrape"

What's new

v1.6.0 (August 19, 2026) had two themes: things that used to fail silently now fail loudly, and your edited text now survives into the documents you send. It came out of a deep empirical template review (PR #347 — 25 fixes, each carrying its own test). The breaking change: all six portal CLIs reject unknown flags after one portal returned the entire 13,862-posting database for a typo'd flag with exit 0. Since then, commits added company-research caching for repeat /apply and /interview lookups (#349), an onboarding warning about public forks at the point of decision (#345/#348), a fix for dotted suffixes like "A.M.B.A." being dropped in company-name salary matching (#356), and a Debian bookworm TeX Live CI leg (#346). Last push: August 23.

Troubleshooting

  1. Your scraped results include jobs you never searched for. A known issue (#331): the scraper occasionally generates "ghost" LinkedIn postings. Fix: sanity-check posting URLs before running /apply, pull latest main for scraper fixes, and treat implausible matches as noise.
  2. Your edits to a cover letter vanish in the final PDF. This was v1.6.0's headline fix area — text not surviving into sent documents. Fix: upgrade past v1.6.0 and re-run; the release specifically made user-written text survive templating.
  3. A portal CLI returns a suspiciously huge result set. Pre-v1.6.0, wrong flag names could return entire databases with exit 0. Fix: upgrade to ≥1.6.0 where unknown flags exit 1 with a JSON error, and always check exit codes in any scripts you build on top.
  4. LaTeX compilation fails on Linux. Missing packages, usually. Install the extras (texlive-latex-extra) or mirror the CI's debian:bookworm leg, which compiles against apt-packaged TeX Live.
  5. You pushed your fork public with personal data in it. Real risk — v1.6.0 added a warning about public forks at the point of decision. Fix: keep profile details in a private fork or untracked local files, and scrub history before making anything public.
