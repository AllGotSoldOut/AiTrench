OpenClaw: Your Personal AI Assistant, On Your Devices, In Your Chats

August 24, 2026

OpenClaw (GitHub, MIT) is a personal AI assistant that runs on your own hardware and shows up in the messaging apps you already use — WhatsApp, Telegram, Slack, Discord, Signal, iMessage, Google Chat. It's built for a single operator: one Gateway process connects your model providers, tools, skills, plugins, and channels. The numbers tell you how much this idea resonates: roughly 387k GitHub stars in under a year, developed openly by the non-profit OpenClaw Foundation.

The pitch is simple: instead of pasting your life into someone else's cloud chatbot, you run the assistant where your data lives, and it reaches you wherever you already are. It was originally built for "Molty", Peter Steinberger's space-lobster assistant — hence the lobster emoji everywhere.

Why you'd actually use it

  • A assistant that texts you back. Connect Telegram or WhatsApp as a channel, then message it from your phone like a person: "summarize the PDF I dropped in my workspace and ping me when done."
  • One brain across every device. The Gateway is the single control plane for sessions and tools; the CLI, TUI, and web Control UI all attach to the same assistant state, so your context doesn't fragment per app.
  • Local model support. Point it at hosted providers or run local models — useful if you don't want conversation content leaving your network at all.
  • Extensible without forking. Skills, tools, and plugins extend behavior; new capabilities usually ship as plugins on the plugin SDK and get shared through ClawHub.
  • Voice and device actions. Companion apps and nodes add voice, Canvas, camera, screen access, and device-local actions on supported platforms.

Getting started

  1. Run the installer (macOS, Linux, Windows; it provisions Node.js if needed): 
    # macOS / Linux / WSL2
curl -fsSL https://openclaw.ai/install.sh | bash
    # Windows PowerShell
iwr -useb https://openclaw.ai/install.ps1 | iex
  2. If you already manage Node yourself (Node 22.22.3+, 24.15+, or 25.9+), install the npm package instead: 
    npm install -g openclaw@latest --allow-scripts=openclaw

    That flag form needs npm 12 or npm 11.16+; on npm 11.15 and earlier drop `--allow-scripts=openclaw`.

  3. Fresh installs launch onboarding automatically. If you installed via npm directly, run: 
    openclaw onboard --install-daemon

    Onboarding verifies model access, creates your workspace, and configures the Gateway.

  4. Check status and open the Control UI: 
    openclaw gateway status
openclaw dashboard

    Send a message in the Control UI to confirm everything works.

  5. Connect a messaging channel (Telegram, WhatsApp, Discord…) following the channels guide, then approve any sender pairing requests: 
    openclaw pairing approve <channel> <code>

Code & config samples

Running from source is a pnpm workspace (plain `npm install` at the root is not supported):

git clone https://github.com/openclaw/openclaw.git
cd openclaw
pnpm install
pnpm build
pnpm ui:build

Everyday CLI surface you'll actually touch:

# daemon + control plane health
openclaw gateway status

# approve an unknown sender pairing request from a DM-capable channel
openclaw pairing approve telegram AB12CD

New capabilities belong in plugins rather than core forks — build against the plugin SDK and publish through ClawHub.

Troubleshooting

  1. `/models` stops working after a config edit and never recovers. Known bug recently patched on main (#128608). Update to the latest build rather than hunting your config.
  2. npm plugin installs fail with newer npm clients. Fixed in v2026.7.1-2 (singleton-array metadata handling). Bump your install before debugging plugin manifests.
  3. Unknown senders can't talk to the bot on DM-capable channels. That's by design — unknown senders get paired by default. Approve them with `openclaw pairing approve <channel> <code>`.
  4. Tools ran outside a sandbox. Tools run on the host for the main session unless you configure sandboxing. Read the security guide and sandboxing docs before connecting other users or exposing the Gateway remotely.
  5. Gateway unreachable after reboot. If you skipped the installer path, make sure the daemon was actually registered — re-run `openclaw onboard --install-daemon`, then check `openclaw gateway status`.
