Awesome Agent Skills: 1,000+ Curated Skills for Claude Code, Codex & Cursor

August 24, 2026

VoltAgent/awesome-agent-skills is a curated directory of agent skills — those SKILL.md-style instruction packages that teach coding agents how to do a specific job. It's sitting at roughly 32,000 stars and climbing, and it's currently one of the fastest-moving repos on GitHub Trending. What separates it from the pile of auto-generated "awesome" lists is stated right in the README: hand-picked skills from real engineering teams — Anthropic, Google Labs, Vercel, Stripe, Cloudflare, Netlify, Trail of Bits, Sentry, Expo, Hugging Face, Figma — plus vetted community contributions. The badge count is at 1,497+ skills and it's still growing daily.

Why does this matter right now? Because agent skills have quietly become the standard way to extend coding agents. Claude Code, Codex, Gemini CLI, Cursor, GitHub Copilot, OpenCode, Windsurf, and Antigravity all read the same basic format now. That means one well-written skill file works across your whole toolchain — and this repo is effectively the package index for them.

Why you'd actually use it

  • Stop re-explaining your stack to your agent. Instead of pasting "we use Stripe Checkout with webhook signature verification" into every session, install a Stripe skill once and every agent that reads it gets the current best-practice flow.
  • Security review you didn't write. Trail of Bits publishes skills here. If you're shipping code without a security pass, pointing your agent at their skill is a cheap upgrade.
  • Framework drift protection. Vercel, Cloudflare, Netlify, and Expo move fast; model training data doesn't. Official-team skills encode the current API surface so your agent stops hallucinating deprecated flags.
  • Cross-tool consistency. Same skill works in Claude Code on your laptop and Codex in CI. One source of truth for "how we do things."
  • Finding what exists. Honestly, half the value is discovery — browsing the categories tells you what agents can now do that you didn't know about last week.

Getting started

There's no installer — skills are just files in a known location. The README has a compatibility table mapping each host tool to its skills path. The general flow:

  1. Browse the list (or the companion site) and pick a skill. 
    https://github.com/VoltAgent/awesome-agent-skills
# browsable site: https://officialskills.sh/
  2. Clone the repo or grab the skill folder you want: 
    git clone https://github.com/VoltAgent/awesome-agent-skills.git
cp -r awesome-agent-skills/skills/<skill-name> .claude/skills/
  3. For Claude Code specifically, drop it under your project's .claude/skills/ directory (or ~/.claude/skills/ for global availability).
  4. For other tools, follow the README's per-tool table — Codex, Cursor, Gemini CLI, and friends each have their own skills directory convention documented there.
  5. Restart your agent session and confirm the skill is picked up (in Claude Code, ask it which skills are loaded).

Skill anatomy

A skill is a folder with a markdown instruction file plus optional scripts and references. A minimal one looks like this:

.claude/skills/stripe-webhooks/
├── SKILL.md          # instructions the agent loads
├── scripts/
│   └── verify_sig.sh # helper the agent may run
└── references/
    └── events.md     # event catalog

The SKILL.md frontmatter declares when the skill should activate:

---
name: stripe-webhooks
description: Verify Stripe webhook signatures and handle
  checkout.session.completed events safely. Use when wiring
  up or debugging Stripe webhooks.
---

1. Never trust the raw body — always verify the signature header first.
2. Use the endpoint secret from `stripe listen` in local dev.
...

The description field is the trigger — write it like a routing rule, not marketing copy.

Troubleshooting

  • Skill isn't being picked up. Cause: wrong directory for your host tool (each agent uses its own path). Fix: check the compatibility table in the README rather than guessing; global vs. project-level paths differ.
  • Agent ignores the skill mid-session. Cause: skills are typically indexed at session start. Fix: restart the session after installing, and make sure the frontmatter description actually matches what you're asking for.
  • Name collisions. Two installed skills with similar names/descriptions confuse routing. Fix: remove duplicates, keep only one skill per concern.
  • Stale vendored copies. If you copied skills months ago, they've likely been updated upstream. Fix: re-sync from the repo instead of editing your local copy in place.
  • Quality variance in community entries. The list is curated but not uniform. Fix: prefer official-team skills where they exist, and read the SKILL.md before letting an agent act on it.

If you use coding agents at all, bookmark it. It's the closest thing this ecosystem has to npm.
