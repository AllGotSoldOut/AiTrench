Anthropic Opened a Community Plugin Marketplace — Here's How to Use It

August 24, 2026

anthropics/claude-plugins-community is the official community plugin marketplace for Claude Cowork and Claude Code. It hit GitHub trending this week at ~1,400 stars, and it changes how you extend Claude: instead of hand-copying slash commands or MCP configs into your project, you install reviewed plugins with one command.

The important architectural detail: this repo is a read-only mirror. The .claude-plugin/marketplace.json file is synced nightly from Anthropic's internal review pipeline. Every plugin in it has been submitted through claude.ai, passed automated security scanning, and been approved for distribution. You can't open a PR against the repo — pull requests are closed automatically. That sounds annoying until you realize what it buys you: nobody can slip a malicious commit into something you're about to install.

Why you'd actually use it

  • You keep retyping the same custom commands across repos. Package your workflow once as a plugin (commands + agents + hooks), then install it everywhere in one line instead of maintaining dotfile copies.
  • Your team wants shared tooling without a monorepo. Point everyone's Claude Code at this marketplace plus your own internal one, and onboarding becomes "run these two commands" rather than "copy these five files."
  • You want MCP servers without manual config surgery. Plugins bundle MCP server definitions alongside commands and hooks, so adding, say, a database inspector doesn't mean hand-editing JSON config files.
  • Claude Cowork users want vetted extensions. Cowork installs plugins from claude.com/plugins, backed by this same directory — everything there has cleared the security scan pipeline.
  • You're evaluating before building your own plugin. The mirror doubles as a browsable catalog of real-world plugin structure — useful as a reference when you write your own.

Getting started

  1. Have Claude Code installed and on your PATH. Verify with: 
    claude --version
  2. Add the community marketplace to Claude Code: 
    claude plugin marketplace add anthropics/claude-plugins-community
    This registers the marketplace under the name claude-community.
  3. Browse what's available. You can read the synced catalog directly on GitHub (.claude-plugin/marketplace.json) or check claude.com/plugins for the browsable version.
  4. Install a plugin by name: 
    claude plugin install <plugin-name>@claude-community
  5. Restart your Claude Code session so the plugin's commands, agents, and hooks load, then try its commands with /.
  6. If you'd rather build your own plugin and publish it: submit via clau.de/plugin-directory-submission. It goes through automated security scanning and review before appearing in the nightly sync. Don't PR the repo — it gets auto-closed.

Related catalogs worth bookmarking: claude-plugins-official for Anthropic-maintained plugins, and knowledge-work-plugins for role-specific bundles.

Code & config samples

A minimal local plugin layout that follows the same conventions the marketplace expects:

my-plugin/
├── .claude-plugin/
│   └── plugin.json
├── commands/
│   └── deploy.md
├── agents/
│   └── reviewer.json
└── hooks/
    └── hooks.json

And the day-to-day management commands:

# list configured marketplaces
claude plugin marketplace list

# refresh the mirror sync
claude plugin marketplace update anthropics/claude-plugins-community

# remove a plugin you no longer want
claude plugin uninstall <plugin-name>@claude-community

(Per official docs for the add/install flow; list/update flags follow standard Claude Code CLI conventions.)

Troubleshooting

  • "Marketplace not found" after adding — you likely typo'd the org/repo slug. It must be exactly anthropics/claude-plugins-community; re-run the marketplace add command.
  • Newly approved plugin isn't showing up — the mirror syncs nightly, so approvals can lag up to a day. Run claude plugin marketplace update anthropics/claude-plugins-community to force a refresh.
  • PR to the repo closed instantly — that's by design. All content flows from the internal review pipeline; submissions go through clau.de/plugin-directory-submission only.
  • Plugin installed but its commands don't appear — running sessions don't hot-load plugins. Restart Claude Code (or start a fresh session) and check again.
  • Name collision with an official plugin — if a plugin exists in both community and official marketplaces, qualify it explicitly with its marketplace suffix (@claude-community vs the official one) when installing.
