OpenLogi: Ditch Logitech Options+ Without Losing Your Mouse's Superpowers

August 24, 2026

OpenLogi (GitHub, Apache-2.0/MIT dual-licensed) is a native, local-first replacement for Logitech Options+, written in Rust with GPUI. It talks to your Logitech mouse, keyboard, and webcam directly over HID++ and UVC — remap buttons, control DPI, tune SmartShift, adjust camera settings — with no account, no telemetry, and no Electron. Around 16k stars since May 2026, trending hard on GitHub and fresh off a Product Hunt launch.

The honest hook: Options+ works, but it's heavy, requires sign-in, has no Linux support, and locks everything behind a GUI. OpenLogi runs light on macOS, Windows, and Linux (a first-class platform here), gives gestures to any physical button, keeps all config in one plain TOML file you can sync between machines, and ships a real CLI alongside the GUI.

Why you'd actually use it

  • You're on Linux with an MX Master. Options+ simply doesn't run there. OpenLogi installs udev rules so you get full HID++ control — battery state, DPI, thumbwheel — without sudo.
  • You want per-app profiles that actually switch. Profile overlays auto-switch on app focus (macOS + Windows; X11/XWayland on Linux). Browser profile gets back/forward on the thumbwheel; Blender profile gets something else entirely.
  • Your config should be version-controlled. One TOML file describes every mapping. Sync it via dotfiles, diff it in git, script it through the CLI.
  • You own a Logitech webcam too. Brio/StreamCam/C920 controls are written straight to UVC hardware, so zoom/focus/exposure changes apply in Meet, Zoom, OBS — everywhere the camera is used. Litra lights are supported as well, including power that follows camera activity.
  • You hate the ratchet toggle dance. SmartShift sensitivity, mode toggles, even a permanent-ratchet panel (`0x2111`), plus per-direction gesture bindings with live capture.

Getting started

  1. Quit Logi Options+ first. Both apps fight over HID++ access and only one can own a given receiver at a time.
  2. macOS 13+ — grab the signed `.dmg` from releases, or use Homebrew: 
    brew install --cask openlogi

    To track the newest GitHub release instead of the official cask autobump:

    brew tap aprilnea/tap
brew install --cask aprilnea/tap/openlogi@latest

    Install either `openlogi` or `openlogi@latest`, not both (per official docs).

  3. Linux — install the package for your distro from the latest release: 
    # Debian / Ubuntu
sudo dpkg -i openlogi_*.deb

# Fedora / RHEL
sudo rpm -i openlogi-*.rpm

# Arch Linux
sudo pacman -U openlogi-*.pkg.tar.zst

    Packages cover x86_64 and arm64 and include udev rules granting user access to `/dev/hidraw*`, `/dev/uinput`, and your mouse's event node. Then enable the background agent:

    systemctl --user enable --now openlogi-agent.service
  4. Windows — signed portable `.zip` or per-user `.msi` (x86_64/arm64) from releases. Both ship `OpenLogi.exe` plus the background agent `openlogi-agent.exe`; keep the two files side by side if you go portable, or the GUI has nothing to connect to.
  5. NixOS users can import the repo's NixOS module instead — it installs the package, udev rules, and starts the agent with your graphical session (see docs/INSTALL-linux.md).
  6. Launch the app, pick your device, start remapping — or drive it headless via the CLI (see docs/USAGE.md).

Code & config samples

Everything lives in one TOML file. A flavor of what you can express:

[app_settings]
# hide the agent tray icon on Windows (GUI toggle is macOS-only)
show_in_menu_bar = false

Beyond basic remapping, the feature set maps to concrete HID++ registers: DPI presets with Cycle/Set-preset actions (`0x2201`), SmartShift mode/sensitivity/ratchet (`0x2111`), native scroll inversion per device (`0x2121`), keyboard static RGB (`0x8070`/`0x8080`). Media key actions use D-Bus MPRIS on Linux; a few macOS-specific actions have no Linux equivalent and become no-ops.

The Actions Ring deserves a mention: an eight-slot, cursor-centered overlay of actions (`ShowActionsRing`) with per-application layouts — like a radial menu summoned under your pointer.

Troubleshooting

  1. Devices don't respond / nothing is detected. Logi Options+ (or Solaar) is still running and holding the receiver. Only one application can own a HID++ device — quit the others before starting OpenLogi.
  2. Linux GUI won't talk to the device without sudo. The udev rules didn't apply. Reboot or reload udev after installing the package; on non-systemd distros follow the manual setup in docs/INSTALL-linux.md.
  3. Windows GUI opens but shows no devices. You're using the portable zip and moved `OpenLogi.exe` away from `openlogi-agent.exe`. The agent owns all device I/O — keep both files side by side, check the tray icon, and restart the agent.
  4. Some actions do nothing on Linux. Expected for macOS-specific actions with no universal equivalent; media keys need D-Bus MPRIS. Also note per-app overlays only work on X11/XWayland right now, not native Wayland.
  5. Config changed under you after an update. The project warns features and config may still change pre-stability. Keep your TOML in git so updates that alter semantics show up as diffs.
