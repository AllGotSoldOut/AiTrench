Apache Maka: A Local-First Agent Workspace That Keeps the Receipts

August 24, 2026

Most agent tools treat your conversation with the model as disposable state in a UI. Apache Maka (Incubating) flips that: it's a local-first agent workspace where every model message, tool call, tool result, permission decision, and termination event is written to an append-only log on your machine. The ~3,000 stars it picked up since May say a lot of people want exactly that.

The pitch in one line: your machine, your data, and a durable record of what the agent actually did. You bring the model — cloud API, local model, or gateway — and Maka runs tools under a sandbox boundary through one Runtime Host shared by the desktop app, the terminal CLI, and the eval harness.

Why you'd actually use it

  • You don't trust an agent near your codebase without an audit trail. Every tool call and its result is saved as execution fact. If a run goes sideways, you can read exactly what happened instead of guessing from the chat transcript.
  • Context trimming shouldn't mean losing evidence. Maka can omit old tool output from the next prompt to keep context short — without deleting the saved record. Long-running refactors stay coherent without amnesia about what was already tried.
  • Crash recovery matters. Runs are resumable after interruption. If your laptop dies mid-turn, you resume instead of restarting from scratch.
  • Permission boundaries by default. Tools that leave the sandbox require approval, runs can be aborted mid-flight, and failures are classified rather than silently swallowed.
  • Reproducible evals. maka eval run <spec> expands declarative multi-arm experiments into task × repetition × subject cells with per-cell scores, usage, cost, and failure reasons — handy if you're comparing models or prompts on real tasks.

Getting started

Honest caveat up front: Maka has no Apache release yet, so the README recommends building from source rather than trusting prebuilt downloads. Desktop currently targets Apple Silicon Macs; Windows is an unsigned preview and Linux isn't supported yet.

1. Install the requirements

  1. Node.js 22.19+ (CI uses Node.js 24)
  2. npm (npm 11 is the current packageManager)
  3. Git
  4. ripgrep, used by Runtime's Grep tool
# macOS (Homebrew)
brew install node git ripgrep

2. Clone and run Desktop

git clone https://github.com/apache/maka.git
cd maka
npm ci
npm run dev

npm run dev starts the desktop environment with HMR. To build every workspace before launching Electron:

npm run dev:full

If Electron's binary was skipped during install (ELECTRON_SKIP_BINARY_DOWNLOAD=1), grab it first:

node node_modules/electron/install.js

3. Connect a model

Maka ships with no bundled model account. On first launch: open Settings → Models, add an API/local/gateway connection, test it, and set a default. Only connections actually wired into Runtime show up as usable models.

4. Use the CLI

npm run build
npm run cli:dev
# one non-interactive turn
npm run cli:dev -- run "Summarize this repository and identify its most important risk"
# durable graph mode
npm run cli:dev -- run --graph "Implement two independent slices, integrate them, then review the result"

Note: graph operators use isolated Git worktrees, so your project needs to be a clean Git worktree first.

Code & config samples

The TUI accepts slash commands to toggle graph mode interactively:

/graph on
/graph off
/graph Refactor the auth module and add tests for the new flow

Built-in tools available to the agent are the usual file-and-shell set — Read, Write, Edit, Bash, Glob, Grep. Computer Use and catalog skills exist but are opt-in and off by default, which is the right default for anything running against your real projects.

Eval specs are declarative files expanded into experiment cells:

maka eval run my-spec.yaml --out ./results/

Each cell gets immutable attempts and a result kernel covering score, normalized usage, attributable cost, duration, status, failure reason, and artifacts.

What's new

There's no tagged release yet — the repo is explicit that nothing published so far is an Apache Software Foundation release, and once source releases exist they'll be signed and approved through the Incubator PMC. Development is active (last push within a day of this writing), with recent work centered on streaming model output, clearer provider errors, crash recovery, and the Graph execution mode. Expect data formats and CLI commands to change while it incubates — pin your checkout if that bothers you.

Troubleshooting

  • npm run dev fails to launch Electron. If dependencies were installed with ELECTRON_SKIP_BINARY_DOWNLOAD=1 (common on CI or flaky networks), the Electron binary is missing. Run node node_modules/electron/install.js, then retry.
  • Grep tool errors at runtime. Runtime shells out to ripgrep. If rg isn't on your PATH, install it (brew install ripgrep) before starting a session.
  • --graph run refuses to start. Graph implementation operators use isolated Git worktrees, which requires a clean working tree. Commit or stash your changes first.
  • Your model connection shows but can't be selected. Maka distinguishes configured, send-ready, and experimental states — a connection not wired into Runtime won't be presented as usable. Re-test it in Settings → Models and check the connection type matches your provider.
  • Windows build triggers SmartScreen warnings. Windows is an unsigned preview tier, not a supported release. That warning is expected; prefer macOS arm64 if you want the supported path.

Maka is early — incubation means formats move — but the core idea, an append-only execution log as the source of truth for agent runs, is the right one. Worth watching, especially if you run agents against production codebases.
